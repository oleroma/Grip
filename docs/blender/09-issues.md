# 9. Issues and loose ends

Everything found while documenting the file that is wrong, fragile, misleading or unused, in one list. Each item says how it was established (**[measured]**, **[wiring]**, **[inferred]**), what it affects and a suggested fix. Nothing here has been changed in the file.

Groups:

- **A. Exports**: the committed or next exported STL files are affected.
- **B. Fragile geometry**: a setting or edit can produce a broken or empty part.
- **C. Misleading values**: a value shown in the file is not the one used, or does nothing.
- **D. Leftovers and naming**: cleanup that changes nothing printed.

## B. Fragile geometry

| # | Issue | Evidence | Effect | Suggested fix |
|---|---|---|---|---|
| B1 | **Triggers are not closed meshes.** L2/R2 and L4/R4 have 1 to 6 non-manifold edges depending on preset; `bevel subd` = 2 adds more (up to 10). In the first run (Blender 5.2.0, Windows), GripX xbox R4 `shift z` 4.2 → 4.62 made the **whole case bottom empty**, while 4.0, 4.3, 4.4, 4.5 and 5.0 were fine. The second run (bpy 5.2.2, Linux) did not reproduce the empty case at subdivision low or very high, but the non-manifold edges are the same. | [measured] | slicer warnings on the trigger STLs; a nearby value can silently delete a case half | make the trigger generator produce closed meshes (merge by distance before the boolean); until then, check the case after trigger edits ([Triggers](parts/triggers.md)) |
| B2 | **`horizontal buttons` off is unstable.** Unrelated edits make the ABXY shaft exactly 2.08 mm shorter and every cap 85 mm³ larger (D-pad similar). | [measured] | the non-horizontal design cannot be trusted as is | only relevant if that design is revived ([Buttons](parts/buttons-and-caps.md)) |
| B3 | **`fill type` = manual is broken.** No preset behind it (7 presets for 8 menu items) and its curve collection `manual indent` is empty. | [wiring]; with body `indent` the case top becomes empty [measured] | choosing it destroys the case | remove the menu item or finish it ([6.4](06-body-types.md#64-indent-a-pattern-pressed-into-the-surface)) |
| B4 | **The lattice is drawn for GripV only.** All 24 curves in `creases and curves` shrinkwrap to `basemesh GripV`. | [wiring]; the GripX lattice bottom is 17,665 mm³ against 30,245 for the hollow bottom, and narrower than the GripX case [measured] | GripX lattice cases do not follow the GripX shape | separate curve sets per basemesh, or project in the node tree onto the current basemesh ([6.6](06-body-types.md#66-lattice-strips-instead-of-a-wall)) |
| B5 | **GripX uses the GripV rib planes.** `ribs` passes `ribs gripv top` to both inputs of its variant switch; `ribs gripx` (`Plane.002`, `Plane.003`) is unused. | [wiring] | GripX shell tops get ribs placed for the GripV shape | connect `ribs gripx` to the GripX input ([6.5](06-body-types.md#65-hollow-the-sdf-shell)) |
| B6 | **Curved bumpers on GripX xbox.** `lever R1L1 base` picks its custom outline per variant/style from `custom shape gripV`, `custom shape gripD` and `custom shape gripX`; the last is **empty**. | [wiring]; with `curved R1L1` on, the xbox bumpers lost 1,095 mm³ and 3.7 mm of height [measured] | curved bumpers cannot be made for the xbox style | add an outline curve to `custom shape gripX` before using `curved R1L1` there ([Bumpers](parts/bumpers.md)) |
| B7 | **Text depends on Windows fonts.** All 11 fonts are loaded from `C:\Windows\Fonts\…`. | B9 | **The split height 40 mm is repeated** as a constant in `cut basemesh`, `plate`, `offset basemesh and slice`, `insert rim`, `pattern field`, and a constant 40 also sits in `screw`. | [wiring] | changing the split in one place breaks the shells, the middle plate or the screws | one global value read by all of them |
| B10 | **The GripV shell top jumps by 2,000 mm³ around the saved screw values.** With `body type` = hollow and `screws hollow` on, the case top is 34,702 mm³ as saved, but 1,700 to 2,000 mm³ lighter for any nearby `screw end slot offset` (0.3, 0.45 to 0.6 against 0.4) or with a screw raised by 0.2. The difference is a thin layer over most of the top, not at the screws. | [measured]; the cause, the SDF voxel grid shifting with the screw bosses, is [inferred] | the shell wall of the released hollow top may change slightly with unrelated edits; volume checks after an edit can mislead | compare wall thickness, not only volume, after shell edits; consider fixing the voxel grid origin or size in the shell groups ([Screws](parts/screws.md#with-shell-bodies)) |
